# Plan: 安东尼之怒 (Anthony's Wrath)

## Technical Context

- 项目现状：仓库中除 `.speckit/` 与 `specs/` 外无任何代码，本功能建立项目骨架。
- 目标运行时：Slay the Spire 1.x + ModTheSpire 加载器；BaseMod 与 StSLib 作为基础 mod 同时加载。
- 构建工具链：Java 8 目标 + Maven（沿用已就绪的环境，不引入 Gradle）。
- 游戏版本锁定：跟随安装的 1.x 最新稳定补丁；具体版本号由构建配置记录，不在本文件重复。
- 扩展方式：BaseMod 的 `CustomMod` 注册自定义模式选项、`CustomCard` 注册诅咒牌、订阅钩子响应游戏事件。
- 时序未知项：抽牌堆的首次洗牌时机、以及非抽牌方式取牌的事件触发情况，均无公开文档可依据，因此本 plan 把机制验证排在任何实现之前（见 Testing Strategy 的 T-P1）。
- 测试框架：不引入任何自动化测试框架（受宪法第一条约束），验证方式为游戏内实测 + 可复现步骤记录。

## Constraints from Constitution and Specification

来自宪法：

- 仅依赖 BaseMod 与 StSLib，不得引入任何第三方库（第一条）。
- 所有面向玩家的文本必须外置于 `strings/` 资源，中英双语 key 一一对应，禁止在代码中硬编码玩家可见字符串（第二条）。
- 本功能不修改原版卡牌、遗物或事件，因此不产生 `patches/vanilla/` 相关改动（第三条）。
- mod 卸载后重新加载曾选择该选项的旧存档必须不崩溃（第四条，对应边界情况）。
- 完成标准为构建通过 + 游戏内实测一次 + 留下可复现步骤（第五条）。

来自规格：

- 选项、诅咒牌、置底行为、抽到即负均由规格条目约束，逐条映射见 Requirement Mapping。
- 贴图占位：开发期只使用**本地占位图**，不把游戏本体的图片提交进仓库，发布前替换为自制资源。
- 每场战斗开始时都重新置底（已确认）。

## Architecture and Components

组件划分与职责，全部位于本 mod 自己的包命名空间内：

1. **主入口（初始化器）**
   实现 BaseMod 的初始化接口与所需订阅者接口，在 `receiveEditCards` 中注册卡牌、在 `receiveAddCustomModeMods` 中注册自定义模式选项、在 `receiveEditStrings` 中加载双语文本资源，并在初始化阶段完成 `BaseMod.subscribe(this)`。
   职责边界：只做注册与订阅，不承载玩法逻辑。

2. **自定义模式选项**
   继承 BaseMod 的自定义模式基类，提供稳定的选项标识（形如 `<modId>:AnthonysWrathOption`）与界面显示文本。该标识是后续一切判断的唯一依据，不得依赖显示名称匹配。

3. **诅咒牌**
   继承 `CustomCard`，构造参数取 `CardType.CURSE` 与 `CardColor.CURSE`，稀有度取诅咒类可用值，目标类型为不指定目标；不实现任何可使用效果（不可打出）；`canUpgrade()` 返回 false（不可升级）；`makeCopy()` 返回新实例。
   文本通过 `CardCrawlGame.languagePack.getCardStrings(ID)` 取得，禁止在类中硬编码。

4. **开局牌组注入**
   由主入口实现 `PostCreateStartingDeck` 订阅者：判定当前一局是否选中了本选项，若选中则向传出的牌组中加入恰好一张诅咒牌。

5. **牌堆位置控制**
   负责在每个洗牌结束点把该诅咒牌移动到抽牌堆底部。具体介入点在 T-P1 验证后确定，候选为战斗开始钩子与洗牌相关的底层介入点；无论选哪个，都必须覆盖战斗开始时的首次洗牌与牌堆耗尽后的重洗。

6. **入手判定**
   负责在诅咒牌进入手牌时触发判负。至少需要一个覆盖抽牌动作的判定点，并由 T-P1 的第二个验证目标确认是否需要补充覆盖"效果直接取牌"的路径。
   判负后不再继续抽牌的机制：判负时置位一个本局内的**已失败标志**（即用于防止重复结算的同一个一次性守卫），后续任何抽牌动作在入口检查到该标志即整段跳过。不额外清空动作队列，也不新增其它干预。

7. **资源与构建**
   `strings/` 下中英双语资源文件、诅咒牌贴图占位、Maven 构建配置（Java 8 编译目标、对 ModTheSpire / BaseMod / StSLib 的本地依赖引用）。

## Data Flow and Interfaces

主要流程与经过的组件：

- **选择选项**：玩家在选择界面勾选选项，游戏把该选项标识记录进玩家的自定义模式项列表；本 mod 在界面展示阶段提供选项文本。
- **开局注入**：新的一局开始、初始牌组生成完成 → 主入口收到 `PostCreateStartingDeck` → 读取玩家的自定义模式项列表 → 若含本选项标识，则向牌组加入一张诅咒牌。此时牌组已固定，诅咒牌随之进入本局的牌库。
- **每次战斗开始**：战斗开始 → 抽牌堆被填充并洗牌 → 牌堆位置控制组件在该洗牌结束后把诅咒牌移到抽牌堆底部 → 玩家回合开始抽牌，诅咒牌位于最底部。
- **战斗中途重洗**：抽牌堆耗尽 → 弃牌堆重新洗入抽牌堆 → 牌堆位置控制组件在新顺序确定后再次把诅咒牌移到抽牌堆底部。
- **抽到该牌**：玩家抽牌 → 入手判定组件识别到该牌进入手牌 → 触发本局失败 → 游戏走本体的失败流程。
- **以效果直接取牌**：由「搜寻」类效果从抽牌堆或弃牌堆取牌入手 → 必须与上一条走同一判定路径。
- **未选择选项**：主入口在开局注入阶段判定为未选中，不加入任何卡牌；其余组件在该局中不产生任何干预。

对外接口就是 BaseMod 的订阅方法签名（`receiveEditCards`、`receiveEditStrings`、`receiveAddCustomModeMods`、`receivePostCreateStartingDeck` 及 T-P1 结论决定的位置控制与入手判定钩子）。本 mod 不向其他 mod 暴露编程接口。

## Dependencies

- **运行时依赖**：BaseMod、StSLib（加载器要求玩家已安装，按宪法第一条这是允许集合的全部）。
- **编译期依赖**：ModTheSpire、BaseMod、StSLib 的 jar；以及游戏本体的桌面版 jar（本地引用，不提交进仓库）。
- **构建工具**：Maven；编译目标与运行目标均为 Java 8，不使用更高版本的语法与 API。
- **打包**：产物为单个 mod jar，内含 `strings/` 资源与贴图；BaseMod 与 StSLib 不打入 jar，由加载器提供。
- **被拒绝的依赖**：任何用于简化事件监听、JSON 解析或测试的第三方库，均因宪法第一条而不予引入。

## Requirement Mapping

- 选项注册与展示（`FR-001`、`FR-011`）：Architecture 第 1、2、7 项；玩家自定义模式项列表是唯一判定依据。
- 开局注入（`FR-002`、`FR-003`）：Architecture 第 4 项，Data Flow 的"开局注入"路径；注入点必须落在"清空初始牌组"之后，具体位置由 T-P1 的第四项探针结论确定。
- 诅咒类别与不可用性（`FR-004`、`FR-005`）：Architecture 第 3 项。
- 不可移除与牌面文本（`FR-012`、`FR-013`）：Architecture 第 3 项与第 7 项；不可移除由底层标记实现，牌面文本在中英双语资源中直接写明，不使用关键词样式或颜色标记。
- 置底行为（`FR-006`、`FR-007`）：Architecture 第 5 项，由 T-P1 确定介入点，由 T-V1 验证。
- 判负时机（`FR-008`）：Architecture 第 6 项，由 T-P1 确定覆盖范围，由 T-V2 验证。
- 判负表现与记录（`FR-009`）：Architecture 第 6 项，失败走游戏本体流程，由 T-V2 验证。
- 单次判负（`FR-010`）：Architecture 第 6 项需要一个本局内的一次性守卫。
- 可观察结果（`SC-001` 至 `SC-005`）：Testing Strategy 的手工检查清单，逐条对应。
- 多次洗牌与空开局牌组（`EC-001`、`EC-002`）：T-P1 需覆盖空开局牌组的钩子顺序与清空时机，T-V1 覆盖多次洗牌。
- 牌被移除后的行为（`EC-003`）：该牌是否受"变化"类效果影响，以参照牌「铃铛的诅咒」的实际结算为准，本 mod 不自行规定；牌堆位置控制组件在找不到该牌时直接跳过，不产生额外判定。
- 判负后的操作与结算顺序（`EC-004`）：T-V2 需确认判负后不再产生可操作结果。
- 主动放弃本局（`EC-005`）：本 mod 不对放弃流程做任何干预。
- 卸载后加载旧存档（`EC-006`）：主入口在读取自定义模式项列表时必须容忍未知标识；由 T-V4 验证。
- 同名选项共存（`EC-007`）：设计约束为"所有判断基于选项标识，禁止基于显示名称"；因需第三方 mod 才能复现，不单独安排验收。
- 非抽牌取牌（`EC-008`）：Architecture 第 6 项的覆盖范围，由 T-P1 第二个验证目标确认。
- 移除界面中的表现（`EC-009`）：Architecture 第 3 项的不可移除标记，由 T-V6 验证。

## Testing Strategy

先验证机制，再写实现；每条验证留下可复现步骤（宪法第五条）。**记录位置就在本节**：每条验证任务完成后，把"怎么操作的、看到什么、结论如何"连同日期补写到对应的 T-V 条目下，作为宪法第五条的落实载体。

- **T-P1 时序探针（先做，只输出日志）**：构建一个仅含日志输出的探针版本，在游戏内推进到战斗开始、抽牌堆耗尽重洗、以及使用一张「搜寻」类卡牌，打印各介入点的触发顺序与抽牌堆内容。必须回答四个问题：首次洗牌发生在哪个钩子之前或之后；哪个介入点能同时覆盖首次洗牌与重洗；以效果直接取牌时哪个判定点会触发；**并在开启"清空初始牌组"的自定义开局下，确认清空与开局牌组创建的先后顺序**（结论决定注入点挂在清空之前还是之后）。结论直接决定 Architecture 第 5、6 项的实现位置。
- **T-V1 置底验证（对应 `SC-001`、`SC-002`、`EC-001`）**：进入战斗后检查抽牌堆顺序；在同一场战斗中通过抽空牌组触发至少两次重洗，每次重洗后重复检查。记录操作步骤与观察结果。
- **T-V2 判负验证（对应 `SC-003`、`FR-008`、`FR-009`）**：让该牌被自然抽到，确认失败在同一次抽牌后立即发生、无额外操作窗口、结算界面显示失败；再用「搜寻」类效果主动取牌，确认同样判负。
- **T-V3 未选中验证（对应 `FR-011`、`SC-004`）**：不选择该选项开一局，逐张比对本局牌组与未安装本 mod 时的牌组。
- **T-V4 卸载验证（对应 `EC-006`）**：禁用 mod 后加载一个曾选择过该选项的存档，确认不崩溃。
- **T-V5 空开局牌组（对应 `EC-002`）**：把初始牌组设为空并选择该选项，确认诅咒牌仍被加入且位于底部。
- **回归要求**：每完成一条实现，重跑 T-V1 至 T-V3，确认没有互相破坏。
- **T-V6 不可移除与牌面文本验证（对应 `FR-012`、`FR-013`、`EC-003`、`EC-009`）**：进入商店移除服务与休息点移除界面，确认该牌不在可移除目标中；用一次"变化"类效果作用于它，确认其表现与参照牌「铃铛的诅咒」一致；检查牌面描述是否与参照牌同样以纯文本写明无法移除，中英两种语言各看一次。
- **构建与资源验收（对应宪法第二条、第五条）**：构建命令成功后，确认产物 jar 存在、命名与放置位置符合记录，并能被 ModTheSpire 正常加载（游戏可启动、加载日志无异常）；中英双语资源文件的 key 集合由**人工比对**确认一一对应（无缺、无多），两份 key 清单与比对结果一并记入本节的验证记录。不引入自动化测试框架，也不把任何比对工具纳入构建流程。
- **不做的测试**：不引入自动化测试框架；探针代码在功能完成后移除，不随发布版本保留。

## Risks and Fallbacks

- **风险：置底介入点不覆盖全部重洗路径**（最可能出问题的一项）。
  兜底：把"在抽牌动作发生前校正抽牌堆底部"作为第二道防线；两道防线可同时存在，重复校正不产生副作用。
- **风险：找不到非抽牌取牌的可靠判定点**，导致以效果取牌时不判负。
  兜底：若底层介入点不可用，则改为在牌位于手牌中的时机做校验；若两条路都不可行，缩减为只覆盖抽牌动作，并把该限制记入规格的边界情况，而不是留下"以为覆盖了"的假象。
- **风险：判负调用方式不正确**，误走"放弃本局"流程或不计入失败记录。
  兜底：以游戏本体的失败流程为准，在 T-V2 中同时核对结算界面与游戏记录；不使用可能被解释为放弃的调用。
- **风险：开局注入时机晚于牌组固定**，导致该牌不进入本局牌库。
  兜底：T-P1 的探针会直接暴露这一点，届时改用更早的介入点或在首场战斗前补齐注入。
- **风险：诅咒牌贴图引用**依赖原版资源或自制资源。
  兜底：开发期只在本地引用占位贴图，**不把游戏本体图片提交进仓库**；发布前替换为自制资源（两个尺寸）。此举与宪法附录中"有意未收录仓库纪律"的取舍一致，属临时开发手段而非长期约定。
- **风险：不可移除的呈现方式与参照牌不一致**。杀戮尖塔 1 没有"永恒"词条，该性质完全靠牌面描述文本表达，措辞偏离参照牌会让玩家看不出它删不掉。
  兜底：牌面文本与参照牌「铃铛的诅咒」对齐（"不能被打出。无法从牌组中移除。"），中英各自照搬游戏内既有用词；T-V6 会在两种语言下各看一次，措辞不对会直接暴露。
- **风险：自定义模式项在读取存档后未恢复**，导致读档后选项判定失效。
  兜底：所有判定都以存档恢复后的玩家自定义模式项列表为准；T-V4 一并验证读档路径。
- **风险：Maven 对游戏本体与基础 mod 的本地依赖引用配置繁琐**，可能拖慢首个可运行版本。
  兜底：先用最小可编译配置打通构建，再补打包细节。
